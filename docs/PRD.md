# PRD: Timeline Map — 2026-09-13

## 背景
Google 停用 Timeline 网页版后，位置历史只以 JSON 导出（手机可直接导出、Takeout 可拉旧数据），但裸 JSON 无法可视化，等于数据在手却"看不到"。需要做一个纯本地运行的查看器，把 Timeline 数据还原成可视化的行程和地点历史。同时该项目是作者的 **portfolio 作品**，将公开分享给大众免费使用——既是实用工具，也是产品思维与工程能力的展示面。

## 目标
①用户导入自己的位置历史 JSON，在一个纯浏览器应用里按日期回放行程、点击地图查看访问历史，**数据全程不出设备**；②公开部署为一个任何人可用、拿得出手的 portfolio 项目（含 Landing 首页、教程、示例数据、开源仓库与文档）。

## 功能范围

- [ ] **功能 1: 空状态首屏 + 多格式 JSON 导入** — 未导入数据时显示引导页（欢迎语 + 导入按钮 + 「如何导出数据」教程入口 + 隐私承诺）；点击导入后支持以下格式：①新版设备导出 `Timeline.json`（direct-array：`semanticSegments[]`/`rawSignals`/`userLocationProfile`，Android 系统设置导出 / iOS Maps App 导出）②`Records.json`（locations[] + activitySegments[]）③Semantic Location History 的 `YYYY_MM.json`（timelineObjects[]：placeVisit/activitySegment）④旧版 `Location History.json`；支持一次导入多个文件；解析在 Web Worker 中执行，文件过大时给出提示 — 验收: 四类样例文件都能导入并统计出行程/停留点数量；空状态引导页可见且导入后消失；格式①含 `rawSignals` 时其原始位置点被导入（兼容大写 `LatLng` 与嵌套 `position.timestamp`），Trips 轨迹渲染可用该数据
- [ ] **功能 2: 日期范围筛选** — 全局时间筛选（起止日期），Trips 与 Places 两个视图共享；按日期过滤行程和停留点；**使用双月历范围选择器**：点起始日 → 点结束日（高亮区间、可前后翻月、标今日），保留「全部 / 近 30 天 / 近 1 年」快捷与单边筛选（只选起点或只选终点）；**跨午夜记录**（起点在范围外、时段与范围重叠，如 01-29 16:58→01-30 08:47 的过夜停留）**保留**，但在列表与 marker 上**显式标注「跨夜 · 自 MM-DD」**（不静默显示昨日记录）；**轨迹顶点裁剪到选定范围内**（地图不越界） — 验收: 选择 2024 年 5 月，地图只显示该月数据；双月历可点选一段范围并高亮；可清除为「不限」；选 2025-01-30 时跨夜停留有「跨夜」标注、地图不出现 01-29 的轨迹点
- [ ] **功能 3: Trips 视图（行程轨迹）** — 选中日期范围内：绘制行驶路线（activitySegment.waypointPath），**全部段按时间顺序（startMs）排序，相邻段间一律自动补衔接线（浅灰细线/虚线，与实测段视觉可区分，tooltip 标注中间 gap 时长），在地图上形成一条无断口的连续时间线轨迹**；衔接线不因段的类型（移動/驾车/步行…）不同、时间重叠或端点点距远近而跳过——「跟時間連」：时间序列上相邻的段端点逐点相接；保留按交通方式着色（实测段不受衔接线影响）；标出停留点（placeVisit 位置与时长）；渲染有点数上限保护，超限降采样。**时间轴模式（默认）**：路线 = 「rawSignals 点 + 语义段（timelinePath）路径点」**按时间排序合并**成一条轨迹——Google raw 只保留 ~30 天，raw 缺失的旧日期自动用语义段轨迹；**已被 raw 覆盖的段跳过、连续重复点（同位置/同时间）折叠**（消除缝合导致的同一轨迹重复绘制）；**每个轨迹顶点都显示为圆点**（轨迹点在 **zoom ≥ 6** 显示为圆点；低 zoom 全景视图（< 6）仅绘制折线以保证性能，折线完整不省略）；**点击任一点弹出 GPS 坐标 + 经过时间 + 「在 Google Maps 開啟」链接**（`timelinePath` 逐点 `time` 直接解析；无逐点时间者不伪造）；停留点用**红/琥珀色** marker（不与路线同色、不参与连线），同样可点开 Google Maps。**左侧面板在时间轴模式显示时间线列表**：轨迹点与停留按时间排序、按日分组，点击飞到该点 — 验收: 导入样例数据后选日期范围，多段行程形成无断口连续轨迹（衔接线与实测段可辨识），路线 + 停留标记可见；选无 rawSignals 的旧日期（如 2025-01-30）时间轴仍显示该日路径；点任一轨迹点弹窗显示坐标 + 经过时间 + Google Maps 链接；左栏时间线列出轨迹点与停留（不只停留点）
- [ ] **功能 4: Places 视图（地图点击查历史）** — 无标记的干净地图；点击任一位置 → 显示该点经纬度 + 以该点为中心、可选半径（1/5/10/50/100 KM）内的所有历史停留点列表（地点名/地址/时间/距离）；半径圈可视化并自动调整 zoom 保证圆完整可见；点击结果列表中的地点可跳转到对应位置；点击处 marker 用高亮色，周围停留点用默认色，视觉层次清晰；**点击停留点 marker 显示该地点历史访问记录**（时间线面板：地点名 + 访问次数 + 每次访问日期/时长）；**日期筛选全局共享**（Trips 与 Places 使用同一日期范围） — 验收: 点击地图 → 浮层显示经纬度 + 半径内停留点列表，切换半径档列表实时变化；点击 marker 颜色区分；点击停留点显示访问历史；Trips/Places 日期筛选联动
- [ ] **功能 5: 本地隐私** — 数据只在内存中，刷新即弃；不写 localStorage/IndexedDB、不接任何分析/遥测 SDK；设置中提供瓦片源自定义（默认 OpenStreetMap），选项旁明示"瓦片请求会把你的 IP 与当前视野坐标发给瓦片服务器"；**外部链接例外须明示**：地图点弹窗默认动作是「**复制坐标**」（纯本机、零网络请求），「在 Google Maps 開啟」保留但明确标注会把坐标与 IP 发送给 Google（外链 opt-in），Landing/设置页隐私文案补「外链例外」说明 — 验收: 不使用 DevTools 时确认无任何网络请求携带原始坐标 JSON；可切换到自定义瓦片源；**不点击外链时，点选任何点都不产生携带坐标的网络请求**；复制坐标不联网
- [ ] **功能 6: 导出教程页** — 常驻入口（主界面可见）：Android 导出步骤（系统设置 → 位置 → 位置服务 → 时间轴 → 导出时间轴数据）、iOS 导出步骤（Google Maps → 头像 → 设置 → 个人内容/位置和隐私 → 导出时间轴数据）、新旧格式说明（设备导出的 Timeline.json vs Takeout 的 Records.json / Semantic Location History）、FAQ（找不到时间轴、换手机丢数据、启用 Timelime 备份） — 验收: 教程页图文步骤完整，Android/iOS 路径区别清楚
- [ ] **功能 7: Landing 首页** — 官网式首页（portfolio 展示面）：产品是什么 + 为什么做 + 功能亮点（行程回放 / 点击查访 / 数据不出设备）+「立即体验」（跳转工具 + 一键载入示例数据）+ 隐私承诺 + 技术栈 + 教程入口；底部加 **「Built with OPC 3.0」section**（通俗语言讲产品如何通过 AI 驱动的产品流程——需求 → 方案 → 开发 → 审查 → 验收逐步成型；**不出现 CEO/Dev/Reviewer/Designer/Security Engineer 等内部角色术语**；含 OPC 3.0 介绍链接）；**Footer 放 "Created by OPC 3.0"**（可点击，指向该 section / 作者 GitHub） — 验收: 访客无需个人数据，从首页即可浏览并一键体验示例数据；footer 品牌露出完整，文案无内部术语
- [ ] **功能 8: 示例数据** — 内置一份可一键加载的模拟 Timeline 数据（覆盖多天行程 + 多地停留，结构对齐真实导出格式），UI 上明显标注"模拟数据，非真实轨迹" — 验收: 点击加载示例数据后，Trips/Places 全部功能可用
- [ ] **功能 9: 更换数据** — 已导入数据后，在日期范围**上方**常驻显示当前载入的文件名与「更换数据」按钮；点击后清空内存数据、回到导入状态（数据仍只存内存，刷新即弃） — 验收: 导入后可见文件名；点「更换数据」回到空状态并可导入另一份 JSON
- [ ] **功能 10: 行程导出（GeoJSON / KML）** — 把当前筛选范围内的轨迹与停留导出为 GeoJSON 或 KML，供其他地图工具使用；**隐私护栏**：导出前确认弹窗列出范围与内容、只导出当前筛选视图、剥离原文件名/装置/路径 metadata、明示「导出文件不受本工具保护」、绝不自动上传或分享链接 — 验收: 导出的 GeoJSON/KML 可被标准工具打开且几何正确；确认弹窗与警示到位；不产生任何网络请求

## 不做
- 离线瓦片打包/自托管瓦片服务器（→ Backlog）
- 行程统计报表（总距离、日均轨迹、地点频次）→ Backlog
- 跨设备/多 Takeout 数据合并去重 → Backlog
- 行程分享/导出截图 → Backlog

> 移动端专项适配：公开分享后访问面扩大，从"不做"移入 KIV（T5）→ **已立项 T24**（2026-09-15 brainstorm：Designer 主张升 P1）。

## 约束
- **纯前端**：React + Vite + TypeScript + Leaflet（OpenStreetMap），无后端
- 数据安全性：位置数据最高敏感，必须"数据不出设备"；**公开 demo 绝不使用作者真实位置数据**
- 性能：多年数据可达数十万坐标点，解析与查询不得阻塞主线程（Web Worker + 空间索引）
- 交付节奏：MVP 优先，浏览器为主，打包为静态站点
- **部署**：静态托管（GitHub Pages / Cloudflare Pages 等），公开仓库 + README + 截图（portfolio 完整性）
- **Theme**：Light/Dark/System 三档切换（CSS 变量，`prefers-color-scheme` 默认）
- **多语言**：英文为主，设置页可切换中文（KIV：需要 i18n 依赖，v2 加入）
