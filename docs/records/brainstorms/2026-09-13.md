# Brainstorms — 2026-09-13

## 11:00 — google-timeline-viewer 产品方向

### 需求
Google 已停用 Timeline 网页版，用户可导出位置历史 JSON 但无工具可看。做一个纯浏览器查看器：
1. 视图 A「Trips」：导入 JSON → 选日期范围 → 显示行程轨迹
2. 视图 B「Places」：无标记地图，点击任一点 → 显示 GPS 信息 + 该点半径内的访问历史（半径 10/100/1000/5000KM）

数据来源格式（已调研确认）：
- 新版 `Records.json`（手机 设置→位置→位置服务→时间轴→导出时间轴数据）：`locations[]`（latitudeE7/longitudeE7/timestampMs/accuracyMeters/source）+ `activitySegments[]`（startLocation/endLocation/duration/activityType/waypointPath）
- 旧版 Takeout `Semantic Location History/YYYY/MM/YYYY_MM.json`：`timelineObjects[]` 含 `placeVisit`（location.name/address/latitudeE7/longitudeE7 + duration）+ `activitySegment`
- 旧版 `Location History.json`：`locations[]`

### 意见
- **Designer**: 顶部 Segmented Control（Trips/Places）+ 全屏常驻地图 + 左侧可收起控制面板（导入/时间/半径共用）——两视图共享数据与时间筛选，是"模式切换"而非并列内容。半径滑杆拖动时 SVG 圆实时跟随并自动 zoom 保证圆完整可见；点击落 pin + 紧贴浮层卡片（lat/lng + N 个停留点），空态与错误态区分；「改筛选绝不重置用户视口」。核心风险是**大文件卡死感**——查询必须 Web Worker + 空间索引 + 渐进渲染，任何 >500ms 操作都要进度反馈。
- **Security Engineer**: 明确推荐**纯前端 SPA**（位置数据最高敏感，数据不出设备从架构上成立）。实现三要点：① 解析放 Web Worker 防主线程卡死，超大小校验提示；② 数据禁止落盘/进 URL hash/localStorage/遥测，刷新即弃；③ 最大的"看似安全实则泄露"风险是**地图瓦片请求**——Leaflet 拉 OSM 瓦片每次请求都带 IP+坐标范围，建议提供自定义瓦片源 + 明示隐私含义。方案 1 + 上述措施 → 不阻塞发布。

### 决定
1. **架构：纯前端 SPA**，React + Vite + TypeScript + Leaflet(OpenStreetMap)。数据全本地处理，刷新即弃。
2. **隐私**：瓦片源可自定义（默认 OSM），设置中明示每次瓦片请求的隐私含义；不接遥测/分析 SDK。
3. **视图结构**：单地图实例 + 顶部 Trips/Places 切换 + 左侧可收起面板（导入/时间筛选共用，Places 加半径档位选择）。
4. **大文件性能**：文件解析放 Web Worker；支持多文件导入（Semantic Location History 按月分文件）；半径查询用空间网格索引预建；轨迹渲染做点数上限保护。
5. **MVP 不含**：离线瓦片打包、行程统计报表、跨设备数据合并。
